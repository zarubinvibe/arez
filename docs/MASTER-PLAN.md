# MASTER-PLAN — фазы Деймоса A-D по зависимости

> REQ-04: этот файл секвенсит фазы A-D по зависимости. REQ-06: фаза A заводится первой волной.
> REQ-11: все четыре фазы отгружаются в релизе, не в бэклоге.

Деймос — нативный пентест-конвейер Ареса, стандалон. Каждая фаза опирается на предыдущую:
находку нельзя ни доказать, ни запереть, ни вести против живой цели без слоя под ней.

## Порядок и зависимости

```
A  recon → exploit → prove            (первая волна, REQ-06/REQ-28)
│    оркестрация 6 сканеров в exit-код; кандидат становится находкой только пройдя prove
│
B  observed-RED анти-театр            (REQ-02/REQ-21/REQ-29 · src/observed-red.ts)
│    prove из фазы A = наблюдаемый RED→GREEN; полый тест (зелёный до фикса) отвергается
│    ЗАВИСИТ ОТ A: без recon→exploit нечего доказывать
│
C  спин-ап живой цели на 127.0.0.1    (REQ-14/REQ-30 · src/phase-c.ts)
│    цель поднимается под своей seatbelt, ноль host-egress, teardown, канареечная проба
│    ЗАВИСИТ ОТ B: живой эксплойт против цели обязан пройти observed-RED, иначе это strix
│
D  scope-манифест + цепочка           (REQ-15/REQ-31 · src/phase-d.ts)
     port-owns-reads (бог не подделает scope) + многошаговая цепочка на MAX_DEPTH=1
     ЗАВИСИТ ОТ C: цепочку ведут против цели, поднятой фазой C, внутри объявленного scope
```

## Почему такой порядок

- **A первой** (REQ-06): срок подпирает замена strix нативным, пока он не врос зависимостью.
  Без runnable-плейбука recon→exploit→prove у Ареса нет захода вообще.
- **B на A**: анти-театр судит РЕЗУЛЬТАТ пробы фазы A. Раньше A ему нечего судить.
- **C на B**: спин-ап нужен только чтобы дать живому эксплойту цель; эксплойт без observed-RED —
  это SARIF-самозаявка strix, ровно то, что Деймос заменяет (LIM-08).
- **D на C**: цепочка и scope имеют смысл против ПОДНЯТОЙ цели с границей; scope без цели — пустой
  манифест, цепочка без цели — нечего сцеплять.
