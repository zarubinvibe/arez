# Безопасность arez

arez - инструмент red-team: он сам поднимает атаку на работающий артефакт и запирает каждую
доказанную дыру регрессионным тестом. Поэтому к его собственной безопасности требования жёстче обычного.

## Инварианты (держатся кодом, не текстом)

- **Арес - лист.** arez не спавнит под-агентов (`daimons: []`). Он сам вектор атаки; фан-аут умножил бы
  радиус поражения единственного бога, который специально пытается всё сломать.
- **generator ≠ verifier.** arez не судит свой патч. Вердикт - exit-код, который гонит координатор вне
  досягаемости атакующего агента. Находка реальна только когда координатор САМ видел RED->GREEN
  (`src/observed-red.ts`); само-отчётный RED не в счёт.
- **Своя песочница.** arez воюет ПРОТИВ песочницы цели, не сбегает из своей: живёт под тем же seatbelt,
  бьёт цель только на `127.0.0.1`, ноль host-egress, ноль Docker и raw-socket.
- **Полый тест отвергается.** Тест, зелёный и до, и после фикса, - театр, а не доказательство; гард в
  `observed-red.ts` (`classifyProof`) режет его.
- **Вендоренное ядро под пином.** `arez doctor` краснеет, если байты вендоренных примитивов olympuz
  разошлись с `vendor/olympuz/PINNED.json`. Дрейф апстрима на чистой машине автоматически недоказуем -
  его ловит только разовый ручной `arez vendor`.

## Секреты

arez не читает `$HOME` и не тестирует на реальных секретах владельца - только на обработке секрета кодом.
Секреты никогда не попадают в код, git или логи. `install.sh` обязан работать на чистом HOME без личных путей.

## Сообщить об уязвимости

Пока проект приватный - через владельца репозитория. Публичный контакт появится при выкладке.
